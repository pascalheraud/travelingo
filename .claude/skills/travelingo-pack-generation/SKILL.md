# Travelingo — Lesson pack generation

Purpose: generate the content for one lesson (`LYY`) of one target language pack (`XX`): learning pack entry, lesson script, audio folder, and translations into all source languages.

Trigger: the user asks to generate, fill in, or write a lesson (e.g. "génère la leçon l02 pour en", "ajoute la leçon L03 du pack it"), or to fix existing lesson content (e.g. "corrige l'audio de p003 en anglais", "il y a une faute dans la phrase p007 du pack fr").

Inputs: `XX` = `TargetLangCode` (see `src/frontend/models.ts`), `LYY` = `LessonId` (`l01`…`l10`, also from `models.ts`).

## Steps

0. **Look up the canonical lesson theme.** `doc/initial-spec.md` §4.1 fixes the 10 lesson slots (`l01`…`l10`) with a specific emoji and title each (e.g. `l01` Politeness & basics 💬, `l02` Airport & flights ✈️, `l07` Getting around 🗺️…). Use that table's emoji/title for `LYY` rather than inventing a theme — if `LYY` isn't in the table or the user wants a different theme, ask for confirmation before deviating from the spec.

1. **Locate the learning pack.** Per `doc/initial-spec.md` §5.2/5.3, the pack JSON is archived per version folder under `src/fixtures/learning/XX/`: find the highest existing `vN` (e.g. `learning/en/v2/en.json` if `v1` and `v2` both exist). Audio lives separately, in a flat, **un-versioned** `learning/XX/audio/` folder shared by every JSON version — never copy or version that folder itself (see step 4).
   - If `learning/XX/` doesn't exist at all, create `learning/XX/v1/XX.json` from scratch following the `LearningPack` shape in `src/frontend/models.ts` (see existing `en` pack for the exact field layout: `uuid`, `targetLang`, `version: "v1"`, `createdAt`, `lessons: []`, each lesson holding its own `phrases: []`). There is no `id` field — `uuid` is the pack's only identity, `targetLang`+`version` (i.e. the folder path) already give the logical name.
   - If `learning/XX/vN/` already exists and you need to add/fix content, **never edit that JSON folder in place** — copy `vN/XX.json` into a new `v{N+1}/` folder first, then make the change there. The old `vN/` folder must remain untouched on disk so it stays a valid permanent archive entry (§5.3). Before creating that `v{N+1}/` folder, ask the user to confirm they want a new pack version now — a version bump is a permanent, user-visible change (it ships as a new archive entry per §5.3 and forces every lesson-content translation pack to also bump per §5.2), so don't create it silently even when the rest of the request (e.g. "generate the lesson script") seems to only need step 3.

2. **Locate the lesson inside the new version's pack.** Look for `LYY` in the pack's `lessons` array.
   - If present, the lesson already has content — ask the user to confirm before regenerating/overwriting it. Targeted fixes (typo in a `target`/`source` phrase, corrected `phonetic`/`grammar`/`complements`) don't need this confirmation and don't go through the rest of this skill's steps — just edit the field in the new version's copy under the same `pNNN` id within that lesson. An audio fix is handled in step 4, not here — don't touch the `audio` field by hand until you know the new filename. Per §5.8, a fix may correct content but must never change a lesson's structure: existing `lessonId`s and, within each lesson, its `pNNN` ids are never renumbered, added to, or removed by a fix — that keeps stored progress (keyed by phrase id) valid across the update.
   - If absent, add a `LessonMeta` entry (`id`, `emoji`, `phrases: []`) and create the corresponding `LearningPhrase` entries (`id`, `target`, `audio`) appended to that lesson's own `phrases` array. Phrase ids restart at `p001` for every lesson — they're unique within their lesson, not pack-wide (don't continue numbering from a previous lesson). Use 10 phrases per lesson unless told otherwise, matching the existing `l01` examples. Set each new phrase's `audio` to `pLL_NNN_v1.mp3` (lesson number `LL` + phrase number `NNN`, its first audio version).
   - Update `createdAt` on the new version's `XX.json` for any change — adding a lesson, adding phrases, or fixing existing phrase/audio content. The version bump itself already happened in step 1 by creating the new `vN+1` folder; a brand-new pack's very first lesson stays in `v1` (there is no prior version to bump from).

3. **Generate the lesson script file.** Next to the new version's `XX.json`, create `src/fixtures/learning/XX/v{N}/XX_LYY.txt` listing the lesson's phrases in target language, one per line, **without phrase ids** — plain `target` text only, one phrase per line, in `p001`…`p010` order (no `pNNN:` prefix, no other text). It is fed as-is to the TTS step below (step 4a), and a TTS voice would otherwise read the id out loud; ordering alone is enough to join it back to the `phrases` array since that array is already in `p001`…`p010` order. Wrap each phrase with `(⏱️=1s)` before and after it (e.g. `(⏱️=1s) Good morning (⏱️=1s)`) — this is the pause marker the TTS voice uses to insert a silence, satisfying step 4a's silence requirement directly in the script rather than as a separate instruction to the voice. Keep it in sync with that lesson's `phrases` added in step 2, and generate it before requesting audio, never after.

4. **Audio: add or fix, in the shared `audio/` folder.** Audio is never duplicated per pack version — there is exactly one `src/fixtures/learning/XX/audio/LYY/` folder, reused by every `vN`. Audio is produced via TTS + the `audio-splitter` tool rather than 10 separate recordings, per the following sub-steps:
   a. **Generate one raw TTS recording covering the whole lesson.** Feed the script file generated in step 3 (already id-free, one phrase per line, in `p001`…`p010` order, each phrase wrapped in `(⏱️=1s) … (⏱️=1s)` pause markers) straight to an AI/TTS voice and have it read the phrases back to back into a single MP3 — the `(⏱️=1s)` markers tell the voice to insert the silence around each phrase, so no separate silence instruction is needed. TTS generation itself is outside this assistant's tools — save the resulting raw file somewhere temporary (e.g. the scratchpad), not under `src/fixtures/` — it's an intermediate artifact, not a pack asset. Reuse the target language's voice/accent from previously generated lessons of the same pack if the user has a preference already established; otherwise ask.
   b. **Prepare `destDir` and hand off the split command.** `destDir` is `src/fixtures/learning/XX/audio/LYY/` — for a new lesson it doesn't exist yet, so create it (an empty dir won't survive in git, so add a placeholder like `.gitkeep` if needed) before handing off the command below. Then, rather than running the `audio-splitter` tool yourself, print the exact command for the user to run once the raw recording from sub-step a is ready: `npm run split -- <raw.mp3> <lessonNum> <version> <destDir>` (documented in `src/tools/audio-splitter/README.md`, spec: `doc/tool-audio-splitter-spec.md`), where `lessonNum` is `LYY`'s numeric part, `version` is the audio version to produce (`1` for a new lesson; see the fix case below for re-recordings), and `<raw.mp3>` is the actual path from sub-step a. The tool fails loudly if it doesn't detect exactly 10 segments — if that happens, do not hand-craft files to work around it; regenerate the raw TTS recording with clearer/longer silences between phrases and have the user re-run the split.
   - New lesson: the prepared `destDir` (`audio/LYY/`) gets filled by the split command with the 10 `pLL_NNN_v1.mp3` files matching the phrase ids set in step 2.
   - Audio fix for an existing phrase: do **not** overwrite or remove the existing `pLL_NNN_v{M}.mp3` files — regenerate the raw TTS recording for the whole lesson (sub-step a) and re-run `audio-splitter` with `version = M+1` into the same `audio/LYY/` folder, producing a fresh `pLL_NNN_v{M+1}.mp3` set alongside the old one. Then update only the fixed phrase's `audio` field in the new pack version's JSON (step 2) to its new `v{M+1}` filename — every other phrase's `audio` field keeps pointing at its existing file (delete the other newly-split `v{M+1}` files you don't need, since only the fixed phrase's audio actually changed).

5. **Complete translations.** For every `SourceLangCode` in `src/frontend/models.ts` (`fr`, `en`, `es`, `de`, `it`, `ro`, `pt`) except `XX` itself if it's also a valid source language, locate or create `src/fixtures/translation/XX-UU/v{N}/XX-UU.json` (same version number as the learning pack's new version — lesson-content translation packs and their learning pack always share the same `v{N}`, per §5.2's compatibility rule):
   - If `translation/XX-UU/` doesn't exist at all, create it at `v1/XX-UU.json` following the `TranslationPack` shape (see existing `en-fr`/`en-it` packs for the exact layout): `uuid`, `learningPackRef` = the learning pack's `uuid`, `targetLang`, `sourceLang`, `version: "v1"`, `createdAt`, `lessons: []`, each lesson holding its own `phrases: []`. No `id` field here either.
   - If `translation/XX-UU/vM/` already exists (`M` = the learning pack's previous version), copy it into the new `v{N}/` folder first — same archive rule as step 1 — then edit the copy.
   - Add a `TranslationLessonMeta` entry for `LYY` (`id`, `title`, `subtitle`, plus its own `phrases: []`, all translated into `UU`).
   - For each phrase added in step 2, add a matching `TranslationPhrase` (`id`, `source`, `phonetic`, `grammar`, `complements`) to that same lesson's `phrases` array, translated/explained for a `UU`-speaking learner of `XX`, in the same style and depth as the existing entries (phonetic transcription readable by a `UU` speaker, grammar/etymology note, 2-4 complement phrases).
   - Check this step actually covers all `SourceLangCode` values, not just the source languages that already have a translation pack for `XX` — a previous run may have left some missing; creating the missing ones is part of this step, not an optional extra.

6. **Sync `src/frontend/languages.ts`.** This file is the manifest stub (`doc/initial-spec.md` §5.4) consumed by `ManifestContext.tsx` — it must reflect reality after any change to a pack:
   - Update the `XX` entry in `LEARNING_LANGUAGES`: `version` (the new `vN`), `lessons` (count of entries in the pack's `lessons` array), `phrases` (sum of `phrases.length` across all lessons), and `translationPacks[UU]` for every source language touched in step 5 (their new version).
   - A pure content fix (step 2's "targeted fix" path) still requires bumping `version` here even though `lessons`/`phrases` counts don't change.

## Out of scope

- **UI strings translation pack** (`translation/{sourceLang}/v{N}/{sourceLang}.json`, §5.1 TYPE 3) is a separate pack family — it has no `targetLang`/lesson content and isn't generated by this skill.

## Notes

- Phrase ids (`pNNN`) are unique within a lesson, not pack-wide — every lesson's `phrases` restarts at `p001`. The join key across the learning pack, the `.txt` script, and every lesson-content translation pack is the pair (`LYY`, `pNNN`), not `pNNN` alone. Audio filenames are `pLL_NNN_v{M}.mp3` — they embed the lesson number `LL` (from `LYY`) alongside the phrase number `NNN`, in addition to living in that lesson's own `audio/LYY/` folder; the `_v{M}` suffix is the audio file's own version (independent of, and usually behind, the pack's `vN`).
- A learning pack's version and its lesson-content translation packs' versions move together: bumping `learning/XX/vN→vN+1` means every `translation/XX-UU/` pack also gets a new `vN+1` folder, even if only the learning pack's content changed (the compatibility rule in §5.2 requires it).
- Keep all generated JSON valid and consistently formatted (2-space indent) with the existing fixtures.
- Generated content is in the target/source language pair; per [[travelingo]], code/comments stay in English but phrase content is written in whatever language the pack requires.

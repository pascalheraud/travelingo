`LessonScreen` flow: validate freezes the question (computes `result`/`pendingGame` via `applyAnswer` but doesn't apply it to the displayed `game` state until Continue is clicked), so the feedback banner and choice highlighting stay stable across the click. Progress is persisted to `ProgressStore` right after validate (not on continue). `lessonDone` (from `AnswerResult.lessonDone`) swaps the screen to `LessonDoneScreen` on the next Continue press.

**Bug fixed (pre-existing, not introduced this session):** `KeyedStore.getSnapshot` in `services/Store.ts` returned a fresh `{ status: 'loading' }` object literal on every call when a key wasn't loaded yet. `useSyncExternalStore` requires a stable reference when nothing changed — the fresh object made React think the store mutated every render, causing "Maximum update depth exceeded" the first time any `KeyedStore`-backed screen (e.g. `LangHomeScreen`) was reached before its data finished loading. Fixed with a shared `LOADING_STATE` sentinel constant. This affects `PacksStore`/`ProgressStore`/`PlacementStore` equally; worth keeping in mind for future `KeyedStore` work.

**Audio:** `AudioService.playPhraseAudio` was already functional (reads from IDB `audio` store, plays via Web Audio API) but nothing populated that store. Per user request, wired a single test file (`public/fixtures/audio/placeholder.mp3`, copied from `sounds/en/hello/hello.mp3`) as a stand-in for every phrase in every language — `PacksService.downloadPackPair` now fetches it once per download and stores it under each phrase's audio key. Real per-phrase recordings are a future replacement; only packs downloaded after this change have audio (existing IndexedDB entries from earlier downloads won't). Clicking a (non-validated) choice plays that phrase's audio immediately (matches the proto's `onSelect`/`playPCM`), not just on manual icon press.

**Deferred (not re-opened, in scope for later sprints):** Review mode UI for `GameService.initReview` (no entry point wired yet — `ReviewButton` from the plan wasn't built). `LessonMode` (`text`/`voice`/...) is persisted but no UI lets the user choose it. Only `l01` tested (matches Sprint 4 fixture scope).

**Tooling gotcha hit this session:** running bare `npx tsc` (no `--noEmit`) in `src/frontend` — e.g. to mimic the `build` script's first step — emits a `.js` sibling next to every `.ts`/`.tsx` file in the tree (`tsconfig.json` has no `noEmit`). Vite's resolver then prefers those stale compiled `.js` files over the real `.tsx` sources for bare imports, so the dev server silently serves old code indefinitely (surviving even hard refreshes, since the server itself is wrong) until the stray `.js` files are deleted. Always use `npx tsc --noEmit` for ad-hoc typechecks in this project — also captured in `.claude/skills/travelingo/SKILL.md`.
